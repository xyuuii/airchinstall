# Airchinstall 使用说明

## 这是什么

Airchinstall 是在受支持的 Arch Live 环境中运行的中文终端陪练工具：左侧始终是你亲手操作的真实 Bash；右侧根据已验证的 UEFI、网络和磁盘事实给出解释、风险和对应 ArchWiki 链接。

它目前**不是完整安装器**：不会自动分区、格式化、安装系统或替你选择磁盘。当前 `0.1` 只覆盖 UEFI、网络和磁盘观察链路。

## 使用前必须知道

- 支持 **官方 Arch Linux x86_64 Live ISO + QEMU/KVM**，以及 **Archboot AArch64 Live ISO + Apple Silicon Parallels**。物理机和其他组合都会被拒绝。
- AArch64 路径使用 Arch Linux ARM 的包仓库和 keyring；下载 Archboot 的 ISO 时必须同时下载同名 `.sig`。启动器会从临时 GPG keyring 中获取并核对固定的 Archboot 签名指纹，验证失败不会创建或挂载虚拟机。
- 需要可用网络，以及一个 OpenAI-compatible `/chat/completions` 接口的 Base URL、模型名和 API Key。API Key 只保存在本次启动的 `/run/airchinstall`，关机即清除。

## 一次完整体验

### 1. 在 Mac 主机准备 QEMU 和官方 ISO

```bash
brew install qemu
```

从 [Arch Linux Downloads](https://archlinux.org/download/) 下载最新 ISO，并按该页面提供的校验和或签名验证文件。假设文件位于 `~/Downloads/archlinux-*.iso`：

```bash
cd /Users/xuyuan/Documents/ChatGPT/airchinstall
./scripts/qemu-mvp.sh --dry-run ~/Downloads/archlinux-*.iso
./scripts/qemu-mvp.sh ~/Downloads/archlinux-*.iso
```

启动器只会创建仓库内的 `.qemu/airchinstall.qcow2`（32 GiB 虚拟磁盘），不会连接 Mac 的物理磁盘。它还会把主机 `127.0.0.1:60022` 转发到虚拟机的 SSH 端口。

### Apple Silicon + Parallels 路径

从 [Archboot AArch64 发布页](https://release.archboot.com/aarch64/latest/iso/) 下载 ISO 和同名 `.sig`，验证签名后运行：

```bash
cd /Users/xuyuan/Documents/ChatGPT/airchinstall
./scripts/parallels-arm-mvp.sh --dry-run ~/Downloads/archboot-*-aarch64-ARCH-*.iso
./scripts/parallels-arm-mvp.sh ~/Downloads/archboot-*-aarch64-ARCH-*.iso
```

脚本会创建名为 `airchinstall-arm` 的 32 GiB ARM64 UEFI 虚拟机，但不会启动它；在 Parallels 控制中心手动启动即可。它会关闭主机磁盘、文件夹、剪贴板和云盘共享。

### 2. 在 Arch Live 里准备访问

QEMU 路径启动后已是 `root`。若要从 Mac 用 SSH 访问，先设置一个临时密码：

```bash
passwd
```

再从 Mac 的另一个终端连接进去：

```bash
ssh -p 60022 root@127.0.0.1
```

Parallels 路径则直接在虚拟机控制台中操作；它没有配置 QEMU 的 `60022` SSH 转发。

两条路径都在 Live 环境中下载并启动项目：

```bash
curl -fL https://github.com/xyuuii/airchinstall/archive/refs/heads/main.tar.gz -o /tmp/airchinstall.tar.gz
bsdtar -xf /tmp/airchinstall.tar.gz -C /root
cd /root/airchinstall-main
./scripts/bootstrap.sh
```

脚本会先检查所支持的 Live ISO、虚拟机和网络；确认后只把运行依赖安装到 Live ISO 的易失层。按提示输入 Base URL、模型名和 API Key。失败时会回到普通救援 Shell，不会自动改动虚拟磁盘。

### 3. 在界面里怎么操作

- 左侧 Bash：自己输入命令；Airchinstall 只观察命令与结果。
- 右上 Mentor：用 `Ctrl+B` 再按右方向键切到该窗格，在底部输入你的目标，例如“我想先确认安装环境是否安全”，然后按 Enter。
- 右下 Wiki：自动显示当前可信操作对应的 ArchWiki 页面与章节。
- 右上按 `Ctrl+D`：展开当前操作的成功条件和详情。不要在左侧 Bash 按这个组合键，那里它是普通 Shell 快捷键。

当前可被识别并自动验证的可信操作只有下面三项；它们全都是只读操作：

```bash
ls /sys/firmware/efi/efivars
ping -c 3 ping.archlinux.org
lsblk -J -o NAME,PATH,SIZE,TYPE,MODEL,RM
```

你仍可在左侧执行其他命令，但模型生成的文本不会变成可复制的命令权威，也不会自动执行任何命令。

### 4. 导出记录或离开

在会话中主动导出脱敏记录：

```bash
airchinstall export-transcript /root/airchinstall-transcript.jsonl
```

导出的文件权限为 `0600`，并会再次脱敏。要临时离开 tmux，按 `Ctrl+B` 后按 `d`；回到会话可运行：

```bash
tmux attach -t airchinstall
```

Live ISO 重启后 `/run/airchinstall`、API Key 和未导出的记录都会消失；QEMU 或 Parallels 的虚拟磁盘会保留在仓库对应的状态目录中。

## 常见情况

- `supported VM required`：确认组合是 x86_64 + QEMU/KVM，或 AArch64 + Parallels；不要在已安装系统或物理机中运行 bootstrap。
- `requires an archiso Live environment`：请从官方 Arch x86_64 ISO 启动。
- `requires an Archboot Live environment`：请从 Archboot AArch64 ISO 启动，而不是在已安装的 Arch Linux ARM 中运行 bootstrap。
- `Cloud AI` 检查失败：核对网络、Base URL、模型名和 API Key；普通 Arch Shell 仍然可用。
- Apple Silicon 上觉得慢：这是 x86_64 ISO 的 QEMU 模拟开销。先用 `--headless` + SSH 可获得更轻量的体验：

```bash
./scripts/qemu-mvp.sh --headless ~/Downloads/archlinux-*.iso
```
